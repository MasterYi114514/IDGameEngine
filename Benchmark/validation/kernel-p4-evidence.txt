2. 逐用例映射：旧用例 -> 新用例，或删除理由
--------------------------------------------------------------------------------
原则：不保留旧 OR 语义；凡新契约下不成立的旧断言一律删除并在此列出理由，
      没有一条是靠放宽断言“变绿”的。

旧 1  plugin.register.accepted
  新 runtime.lifecycle.start_ok
  说明：新契约没有逐个描述符登记入口（计划书 10.1）；“计划被接受”由 start 的预检 + 进入 Ready 表达。

旧 2  plugin.register.duplicate
  新 runtime.plan.duplicate_identity（重复身份 -> PlanInvalidRecord，plugin=1）
  说明：产品内身份唯一由运行期计划预检把关；编译期同名由 DuplicatePlugin 拒绝
        （validation/production/src/cases/case_duplicate_plugin.cpp）。

旧 3  plugin.register.count
  删  理由：registered_count() 随旧登记入口一起退役，没有等价访问器；计划条数由 plugin_count
        与执行序列（runtime.order.follows_plan）证明。

旧 4  plugin.init.success
  新 runtime.lifecycle.start_ok（Ready）

旧 5  plugin.topo.chain_order
  新 runtime.order.follows_plan
  说明：records 故意倒序（C,B,A）+ topo_order 显式 A,B,C，断言 register/init 序列 = RARBRCIAIBIC，
        证明运行期只认计划给序、不按 records 下标执行；拓扑求解本身属编译期
        （validation/production/src/positive/positive_graph.cpp）。

旧 6  plugin.lifecycle.sequence
  新 runtime.lifecycle.sequence（期望串与旧用例完全相同：RARBRCIAIBICSCSBSAUCUBUA）

旧 7  plugin.shutdown.clears_registry
  新 runtime.shutdown.clears_slots + runtime.lifecycle.shutdown_ok
  说明：旧断言看“注册表与拓扑序清空”，新契约看“回到 Idle 且 64 槽全空”。

旧 8  plugin.lifecycle.reinit
  新 runtime.lifecycle.retry（同一计划关闭后再次 start 成功并完整走完四阶段）

旧 9  plugin.init.empty_graph
  新 runtime.zero_plugins.start / runtime.zero_plugins.shutdown（显式空数组计划，零回调）
  说明：全空指针视图（records 等为 nullptr）由 validation/runtime 的独立进程探针覆盖，
        不放进官方套件，避免断言回退时整份报告丢失。

旧 10 plugin.register.capacity_128
旧 12 plugin.init.capacity_128
  新 runtime.capacity.128 / runtime.capacity.128_close（128 条记录的计划走完整生命周期）

旧 11 plugin.register.capacity_129
  新 runtime.capacity.129（PlanTooManyPlugins；数组指针全空，若先索引再校验会崩溃而不是返回错误）

旧 13 plugin.dag.diamond_init
  新 runtime.diamond.start_ok

旧 14 plugin.dag.diamond_order
  新 runtime.diamond.order
  说明：运行期不做图推理，用例锁定“计划顺序被逐字执行”（records 倒序 D,C,B,A + topo A,B,C,D）；
        菱形偏序本身的正确性属编译期，见 validation/production 的 positive_graph。

旧 15 plugin.dag.compatible_whitelist（旧 OR：任一候选达标即可）
  新 assembly.binding.ambiguous + assembly.binding.old_new + runtime.plan.two_slot_providers
  说明：新契约是“产品级唯一 provider”（计划书 6.2 / 6.4）：
        · 两个候选都选中 -> AmbiguousProvider，不挑第一个/最新；
        · 一旧一新同时启用 -> 仍是 AmbiguousProvider（名称唯一先于版本，修订只用于唯一候选的接口校验）；
        · 运行期边界上，同一槽两个提供者的计划直接 PlanInvalidSlotOwner。
        “任一候选即可满足”在新契约下不存在，运行期也不再做候选搜索。

旧 16 plugin.dag.whitelist_order
  删  理由：provider 在编译期唯一绑定，运行期不存在“达标后端排在下游之前”的选择过程；
        合法绑定的正例见 validation/production/src/positive/positive_graph.cpp 与
        positive_ownership.cpp。

旧 17 [SKIP] plugin.dag.missing_dependency
  新 assembly.binding.missing（MissingProvider，真实断言，candidate_match_count == 0）
  说明：旧跳过理由是 Fatal/abort；新契约在编译期返回结构化错误，因此不再 skip。

旧 18 [SKIP] plugin.dag.cycle
  新 assembly.graph.cycle（Cycle + phase == Graph，真实断言）
  说明：同上，环检测已前移到编译期结构化诊断，运行期不存在该 Fatal 路径。

旧 19 [SKIP] plugin.dag.dependencies_over_32
  删  理由：需求组上限属编译期结构校验（TooManyRequirements），运行期计划里根本没有依赖信息，
        没有可断言的运行期行为。覆盖位置：validation/production/src/cases/
        case_too_many_requirements.cpp（33 组必须拒绝，32 组为同环境合法对照）。

旧 20 [SKIP] plugin.register.null_descriptor
  删  理由：描述符登记入口退役，空描述符这个失败路径不存在；计划视图的空指针/空名由
        runtime.plan 预检覆盖（PlanNullPointer / PlanInvalidRecord，见 validation/runtime plan 组）。

旧 21 [SKIP] plugin.register.after_init
  新 runtime.state.already_started（Ready 重复 start -> AlreadyStarted 且不执行任何回调）
  说明：旧断言是 ID_KERNEL_ASSERT -> abort；新契约是可恢复错误码，必须真实断言。

旧 22 [SKIP] plugin.init.on_init_failure
  新 runtime.init_fail.middle + runtime.init_fail.rollback_order + runtime.init_fail.slots_cleared
     + runtime.init_fail.retry + runtime.init_fail.retry_order
  说明：失败插件自身 on_shutdown、已注册全集逆序 on_unload、槽位清空、可再次 start，
        序列断言 RARBRCIAIBSBSAUCUBUA（中间插件 B 失败）。旧“回滚不可达”的 skip 已不成立。

旧 23 slot.store_and_load
  新 runtime.slot.publish_ok + runtime.slot.publish_and_read

旧 24 slot.overwrite_last_wins（后写覆盖）
  新 runtime.slot.duplicate_publish + runtime.slot.duplicate_rollback
  说明：新契约显式拒绝同槽重复发布（ServiceDuplicatePublish），并让 start 回滚；
        “后写覆盖”被有意删除，不是放宽。

旧 25 slot.independent
  新 runtime.slot.two_slots（同一插件两槽各自取回自己的表）+ runtime.slot.unowned_empty

旧 26 slot.unregister（写 nullptr 即卸下）
  新 runtime.slot.null_publish + runtime.slot.null_rollback（publish(nullptr) -> ServiceTableNull）
     + runtime.slot.revoke_on_unload（注销只能走 revoke_service，关闭后槽全空）

旧 27 [SKIP] slot.out_of_range（旧接口 UB，不测）
  新 runtime.slot.out_of_range（槽 64 -> ServiceSlotOutOfRange，先拒绝后索引，真实断言）

旧 28 [SKIP] slot.concurrent_write
  保留 Skip（本轮唯一保留的插件侧 skip）
  理由：新契约仍不提供并发写：publish/revoke 只允许在宿主控制线程的生命周期回调内
        （PluginRuntime.hpp 第 5 条；计划书 10.3 / 11.3）。这不是“可返回错误却被跳过”，
        而是契约明确不存在，写进 Skip 文本里。

新增（旧套件没有对应项、但属于新契约必测）：
  runtime.slot.owner_mismatch / runtime.slot.owner_control   写别人的槽被拒 + 同计划合法对照
  runtime.slot.ready_write_rejected / runtime.slot.ready_preserved / runtime.slot.ready_shutdown
  runtime.state.reentry_busy / runtime.state.reentry_shutdown / runtime.state.reentry_flow
  runtime.plan.revision_zero                                 接口修订 0 不能冒充有效修订
  runtime.domain.idle_before / runtime.domain.idle_after     用例集前后置条件

覆盖面核对（不净减少）：
  旧：20 条有判定的插件/槽用例 + 8 条 skip（6 条插件侧 + 2 条槽位侧）；
  新：45 条运行期/编译期插件用例（+2 条域前后置）= 47 条 + 1 条 skip。
  与插件无关的 55 条（type_id / hash / log / arena / memory）逐字未动，全部 PASS。

6 条 skip 逐条原因（全部不是“可返回错误却跳过”）：
  1) log.assert_dispatch      report_assert 的契约就是 Level::Fatal -> abort（不可恢复）；
                              在进程内触发会杀掉整套测试，按 methodology.md 第 4 节要求隔离。
  2) log.set_sink_nullptr     set_sink(nullptr) 走 report_assert -> abort（同上，头文件契约如此）。
  3) memory.free.interior_pointer  契约是破坏空闲链（未定义行为），不是可返回错误。
  4) memory.free.double_free       契约是破坏空闲链（未定义行为）。
  5) memory.large.magic_collision  64KB 对齐大对象页首 magic 误判是已知未修缺口（id-kernel K1）。
  6) runtime.slot.concurrent_write 新契约明确不提供并发写（见旧 28）。

4. 新增用例的判定方式（不是“非空/固定文案”）
--------------------------------------------------------------------------------
· 调用序列：整串字符串相等，detail 打印“期望 X 实际 Y”（如 RARBRCIAIBICSCSBSAUCUBUA）。
· 错误码：PluginRuntimeError / PluginCompileTime::PluginError 枚举相等，并核 phase / plugin / slot。
· 槽位：指针相等 + 表内 magic 相等；关闭后逐槽遍历断言 64 项全空。
· 编译期结论：kPlanAmbiguous / kPlanOldAndNew / kPlanMissing / kPlanCycle 都是 inline constexpr，
  sort_and_validate 在编译期求值，Check 读取的是已求值结果（同时受编译器常量求值约束）。
· 每个失败用例后面都紧跟同环境合法对照（runtime.slot.owner_control、runtime.init_fail.retry、
  runtime.lifecycle.retry），避免“环境坏了所以全失败”的假通过。

发现 F-P4-1：P0 原型仍直接引用旧运行期单例，会阻塞内核删除该 API。
  Benchmark/validation/prototype/src/apps/PrototypeMain.cpp:37
  Benchmark/validation/prototype/src/apps/ZeroPluginMain.cpp:27
  Benchmark/validation/prototype/plugins/fixture_alpha/src/FixtureAlphaModule.cpp:39
  Benchmark/validation/prototype/plugins/fixture_beta/src/FixtureBetaModule.cpp:39
  形态：static_cast<const void*>(&ID::PluginManager::instance())，只用于“跨模块唯一内核实例”探针，
        不是登记/拓扑调用。该目标由 ID_BUILD_VALIDATION_PROTOTYPE（默认 OFF）控制。
  影响：内核一旦删除 PluginManager 运行期单例，把该开关打开时原型目标会编译失败；
        P1/P2/P3 校验目标与官方 Benchmark 不受影响。
  建议（由 owner 决定）：把这四处探针指向 PluginRuntime::instance()（同一个“唯一内核实例”语义），
        或将该原型标记为历史资产并从默认校验流程中摘除。本轮未改，因为不在授权写范围内。
