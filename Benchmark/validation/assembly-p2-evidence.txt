2.5 接口 / 零插件 / 无槽位混合的真实运行

  ID.Fixture.Core 是 module 且提供槽 60，ID.Fixture.Math 是 module 但 provides 无槽位。
  真实运行链路：Engine::start -> runtime 按 plan 拓扑序回调 -> Math 的 on_init 通过

  宿主侧 new/delete 经 IDPluginStub 走内核分配器 -> Engine::shutdown 逆序回收。
  运行结果 exit 0、3 行 PASS（失败会保留：驱动器把非 0 与 PASS 行数不足都记为批次问题）。
  运行期"无槽位 + 有槽位混合 provision"的细粒度断言见第 1.2 节 provision 组。

2.6 改坏构建证据：C++ 静态校验必须按具体错误类别拒绝
  方法：把某次真实构建生成的 IDAssembly.generated.hpp 复制到独立目录，**只改一行**证据，
  然后编译两个独立 TU（都不链接、不改 Assemble 源码）：

        -> 必须编译失败（改坏的证据进不了产品）

        -> 必须编译失败（证明 (a) 的断言不是空转）
