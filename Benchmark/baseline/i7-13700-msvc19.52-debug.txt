[4] 组合与更新规则
  - 组合边界：本文件取自 math-both 组合。math-scalar / math-simd 单 backend 组合与它同编译器、
    同构建类型、同 flags、同输入数据，沿用同一基线；若某组合连续两次出现 |ratio-1| > 20%，
    必须按 §2D 为该组合单独标定，不得就地调整本文件数值。
  - 更新方式：确认后覆盖更新 [3]，并在 [2] 追加一条"旧值 -> 新值 + 理由 + 对既有报告可比性的影响"。
  - 只允许在同机器、同编译器、同构建类型、同 flags、同精度模式、同输入数据下沿用；换机器 / 换编译器
    版本 / 改 flags / 改被测量必须新建对应文件，不得在本文件上借用。
  - git 提交信息由主 Agent 填写；本文件只负责记录口径变更与数值来源。

[5] 未闭合项（本文件不闭合下列问题，读报告时不得当成已有结论）
  - 未闭合项① 绝对质量仍缺独立下界（regression ≠ 快）：本文件 [3] 的参考值是本机同配置的
    历史实测中位数，因此 ratio ≈ 1 只证明"相对该基线未退化"，**不证明"快"**。绝对快慢需要
    一个与 DUT 实现无关的下界，本域目前三种 basis 都拿不到：
      · theoretical：指令级下界被" DUT 与对照同码"掩盖，给不出比 DUT 更硬的界；
      · hardware ：L1 命中 4–5 cycles 是访存延迟，不是一次 vec4 加法 / 一次矩阵访问的下界；
      · os-baseline：同轮等价手写对照在多条指标上与 DUT 生成逐字相同机器码（见 [2]），
        此时 ratio ≡ 1，参考值循环论证。Debug 下两侧差异来自 -O0 的调用/取址形态，
        更不是"实现质量"的下界。
  - 未闭合项② 跨编译器/跨配置的绝对差异未被解释：MinGW 与 MSVC 的同名指标可差一个数量级，
    Debug 与 Release 之间还差 -O0 / 标量展开一个量级。本文件只按配置各自持有参考值，
    不解释差异来源，也不得据此判断哪个编译器"更好"。
  - 关闭条件：新增一条与实现无关的下界证据（同轮**非等价**对照，或公开硬件规格的完整推导式），
    按 skills/benchmark/references/grading.md §2 写明推导式与参数出处并单独取证。关闭之前，
    报告里的 ratio 与 grade 只能读作 regression 门槛，不得写成绝对性能结论。
