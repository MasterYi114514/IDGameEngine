[2] 口径变更记录（旧 -> 新；本次是该文件首次建立）
  旧口径 : basis = os-baseline，reference_ns = 同轮等价手写对照值 × 目标倍数 1.0。
  问题   : 参考值循环论证（B-1）。vec.add.latency / mat.access.const_index /
           mat.access.proxy_const_index 的 DUT 与对照生成**逐字相同**的机器码（证据
           Benchmark/build/math-both-mingw-release/machine-code-evidence.txt 第 3.1 / 3.3 节的 GCC 侧
           与该文件第 4 节的 MSVC 侧符号统计：AccessConst/ProxyConst 均为 calls=0 / indirect=0 /
           vaddss=1）；此时 ratio ≡ 1。反向的问题同样存在：MSVC 不把 Scalar 的 vec4 运算矢量化，
           vec.add.throughput 相对对照 4.17× → 旧报告给 terrible，但那是"编译器差异"而不是回归；
           SIMD 侧相对标量手写对照出现 0.23×/0.30×/0.40× → 旧报告给 world-class，同样不是绝对质量结论。
  新口径 : basis = regression，reference_ns = 本文件 [3] 表里的历史实测中位数；
           允许回退幅度 0%；同轮对照降级为 note 里的披露项（"同轮对照 X ns，DUT/对照 R×"），
           继续披露 DUT 与等价手写实现的差距，但不再进入评级。
  影响   : 上述 terrible 与 world-class 不再出现；此后报告只表达"相对本基线是否退化"。
           旧报告（os-baseline 口径）不可与本基线混用。
  未改   : 评级带宽（grading.md §5）、两域容差表、测量协议、被测量与输入数据；本次未修改 grading.md。
  未做   : 没有为提高 ratio 调低任何值（首次建立，不是"调值"）；没有删除任何既有证据文件
           （含首轮 [FAIL] vec3.cross_orthogonal 的 build/math-both-msvc-release/math-both-msvc-release-run1.txt）。

[4] 组合与更新规则
  - 组合边界：本文件取自 math-both 组合。math-scalar / math-simd 单 backend 组合与它同编译器、
    同构建类型、同 flags、同输入数据，沿用同一基线；若某组合连续两次出现 |ratio-1| > 20%，
    必须按 §2D 为该组合单独标定，不得就地调整本文件数值。
  - 更新方式：确认后覆盖更新 [3]，并在 [2] 追加一条"旧值 -> 新值 + 理由 + 对既有报告可比性的影响"。
  - 只允许在同机器、同编译器、同构建类型、同 flags、同精度模式、同输入数据下沿用；换机器 / 换编译器
    版本 / 改 flags / 改被测量必须新建对应文件，不得在本文件上借用。
  - git 提交信息由主 Agent 填写；本文件只负责记录口径变更与数值来源。

[5] 未闭合项（本文件不闭合下列问题，读报告时不得当成已有结论）
  - 未闭合项① 绝对质量仍缺独立下界（regression ≠ 快）：本文件 [3] 的参考值是本机同配置的
    历史实测中位数，因此 ratio ≈ 1 只证明"相对该基线未退化"，**不证明"快"**。绝对快慢需要
    一个与 DUT 实现无关的下界，本域目前三种 basis 都拿不到：
      · theoretical：指令级下界被" DUT 与对照同码"掩盖，给不出比 DUT 更硬的界；
      · hardware ：L1 命中 4–5 cycles 是访存延迟，不是一次 vec4 加法 / 一次矩阵访问的下界；
      · os-baseline：同轮等价手写对照在多条指标上与 DUT 生成逐字相同机器码（见 [2]），
        此时 ratio ≡ 1，参考值循环论证；MSVC 侧另有反向问题——不把 Scalar 的 vec4 运算
        矢量化而产生的 4.17× 是编译器差异，同样不是下界。
  - 未闭合项② 跨编译器/跨配置的绝对差异未被解释：MinGW 与 MSVC 的同名指标可差一个数量级
    （如 vec.normalize 0.99 ns vs 3.11 ns）。本文件只按配置各自持有参考值，不解释差异来源，
    也不得据此判断哪个编译器"更好"。
  - 关闭条件：新增一条与实现无关的下界证据（同轮**非等价**对照，或公开硬件规格的完整推导式），
    按 skills/benchmark/references/grading.md §2 写明推导式与参数出处并单独取证。关闭之前，
    报告里的 ratio 与 grade 只能读作 regression 门槛，不得写成绝对性能结论。
