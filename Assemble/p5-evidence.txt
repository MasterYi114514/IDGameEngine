IDGameEngine P4/P5 实施取证（正式切换 + 交付/构建矩阵/契约固化）
================================================================================
记录时间：本轮执行（机器：Windows 11 + PowerShell 5.1，工程根 F:\IDGameEngine）
工具链（本次实测，不是跨机器承诺）：CMake 4.4.4、GNU 16.2.0 (MinGW-w64, x86_64-posix-seh)、
  MinGW Makefiles 生成器、gcc-ar/gcc-ranlib 存在。
所有命令的 CWD 均为 F:\IDGameEngine，除非另行标注。

--------------------------------------------------------------------------------
0. 结论摘要
--------------------------------------------------------------------------------
- P4：旧运行期插件 API 已删除（单例、逐个描述符登记、initialize_all、shutdown_all、运行期
  get_service/register_service、Kahn/OR 排序实现），`PluginManager` 变成不可实例化的纯编译期门面，
  `ID/src/Kernel/PluginManager.cpp` 整个文件删除；Sandbox 改为经 `IDGameEngine` + `ID::Engine::start/shutdown`
  消费产品并真实运行通过。
- P5：性能参数与 IPO 归位到 `cmake/IDFlags.cmake`；三个公共 preset（dev / dev-mono / ship）在本机
  （user presets 补 MinGW 生成器）全部 configure+build 通过；ship 不构建宿主/测试；输出按
  `<build>/out/<shared|static>/` 隔离，同一 build dir 内两种模式实测共存；安装到临时前缀后在新构建目录
  `find_package(IDGameEngine)` 消费成功并真实 start/shutdown；产品指纹在 catalog 与 profile 顺序翻转后不变。
- 未完成/未验证：MSVC 与 clang（本机不存在）；Benchmark 的 `validation/prototype` 4 处旧 API 探针（另一 owner）；
  `get_service` 的回归性能未测量。

5. 已知风险 / 需要协调
--------------------------------------------------------------------------------
1. 输出路径变更：旧文档与脚本里的 `<engine>/bin/bin/Sandbox.exe`、`<engine>/bin/lib/*.a` 不再产生，
   现在分别是 `<build>/out/<shared|static>/bin` 与 `<build>/out/<shared|static>/lib`。
   `skills/shell-operation/SKILL.md` 的产物路径与"OFF/ON 共用 bin"描述已过期，需要其 owner 同步（不在本轮授权内）。
2. `Sandbox` 现在必须有 `ID_ASSEMBLY_PROFILE` 才能构建。本轮收口把口径固定为：`ID_BUILD_SANDBOX`
   默认 OFF，未要求宿主时跳过并打印一条 STATUS 说明；显式 `-DID_BUILD_SANDBOX=ON` 却没有 profile 时，
   在配置期直接失败（Sandbox/CMakeLists.txt 的门卫可达）并给出二选一的可操作提示。
3. Benchmark 的 `validation/prototype` 探针待 owner 迁移；迁移完成前不要打开 `ID_BUILD_VALIDATION_PROTOTYPE`。
4. MinGW + IPO 依赖 `gcc-ar`/`gcc-ranlib`；缺失时会退回 `ar` 并打印一次提示（归档符号索引可能不完整，
   属于工具链限制，不是本项目代码问题）。
5. 既有不一致（本轮未改，属 Benchmark owner 范围）：`Assemble/tests/consumer/AssemblySmoke.cpp` 现在打印 4 行
   `[PASS]`，而 `Benchmark/validation/assembly/cmake/RunAssemblyValidation.cmake` 的判定要求
   `SMOKE_PASS_LINES == 3`；两者需要 owner 对齐，否则该驱动器会报"只打印了 4 行"。
6. 文档残留：`skills/cpp-style/SKILL.md` 的 `PluginDescriptor` / `PluginManager.cpp` 示例与"C++ 导出"说法已在本轮
   收口修复中同步（见第 6 节 6.1）；`skills/benchmark/SKILL.md` 仍写 `Assemble` "尚未建立" 且用
   `<engine>/bin/bin/Benchmark.exe`、`skills/shell-operation/SKILL.md` 仍写共用 `bin` 的产物路径——两者属各自 owner，
   不在本轮授权内。
7. 本文件是执行取证，不是性能报告；不包含任何评级或性能结论。

7.3 MSVC 下的真实缺陷：/WHOLEARCHIVE 只加链接参数，没有建立构建依赖
   干净目录复现（CWD=F:\IDGameEngine，configure 参数与 7.2 相同，只换 -B cmake-build-msvc-p5-order）：
     cmake --build ... --target IDFixtureCore --parallel                                    exit 1（LNK1356，同上）
     cmake --build ... --config Release --parallel（全量 all）                               exit 1（LNK1356，同上）
       —— 并行下 IDFixtureCore 先链接，IDPluginStub.vcxproj 随后才产出 .lib
   根因（代码事实）：
     Assemble/cmake/IDGenerateAssembly.cmake:414-418
       MSVC 分支：target_link_options(${TARGET} PRIVATE "/WHOLEARCHIVE:$<TARGET_FILE:IDPluginStub>")
       GNU  分支：target_link_libraries(${TARGET} PRIVATE "-Wl,--whole-archive" IDPluginStub "-Wl,--no-whole-archive")
     target_link_options 里的 $<TARGET_FILE:...> 只展开成路径，不产生构建期依赖；
     生成的 Assemble/plugins/IDFixtureCore/IDFixtureCore.vcxproj 只有
       <AdditionalOptions>%(AdditionalOptions) /machine:x64 /WHOLEARCHIVE:<...>/IDPluginStub.lib</AdditionalOptions>
     没有任何 IDPluginStub 的 ProjectReference 或库项。GNU 分支走 target_link_libraries，天然有依赖边，
     MinGW Makefiles 下因此掩盖了这个问题（此前 P5 构建通过不代表该分支可移植）。
   处理：本轮可写范围不含 Assemble/**，只记录不修。候选修法（供 owner 决策，任选其一）：
     a) MSVC 分支同时 target_link_libraries(${TARGET} PRIVATE IDPluginStub)，再保留 /WHOLEARCHIVE 选项；
     b) MSVC 分支 add_dependencies(${TARGET} IDPluginStub)（只补排序，不改链接语义）；
     c) 改用 CMake 3.24+ 的 $<LINK_LIBRARY:WHOLE_ARCHIVE,IDPluginStub>，一个分支覆盖两种工具链。
   影响：MSVC / 多配置生成器上 `--target <单个插件>` 与并行全量构建都不可靠（先构建过桩的树重试可通过）。
