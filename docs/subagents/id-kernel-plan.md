## 3. 工作包 K1：大对象元数据识别（优先）

**缺陷：** 64KB/更高对齐时用户指针位于页首，真实 header 位于前页；Free/Realloc 仍先把用户页解释为 Slab。`find_large_header` 也先接受同页 magic + offset，因此合法用户内容影响分配器类型判断。

**证据：** `ID/src/Kernel/Memory.cpp` 的 `allocate_large` 197–199，`find_large_header` 230–244，`ID_AlignedFree` 368–380，`ID_AlignedRealloc` 405–418。

**实施目标：** 按布局确定元数据位置，页首用户指针优先明确处理前页，禁止用用户数据作为类型权威；同时修正 Free 与 Realloc。保留原始映射地址，检查 header 指向原用户指针。

**验收：** 64KB/128KB 对齐、不同 size，以及用户首部写 Slab magic、Large magic、offset 0 等任意合法数据；释放/重分配行为不变，内容保存正确，统计不误扣。普通大对象和小对象不退化。

**范围：** 默认 `ID/**`；测试或 Sandbox 修改必须在本次交接中列入。

## 4. 工作包 K2：算术、对象生命周期与失败契约

### K2-A：checked arithmetic 和 Arena

- `LinearArena.hpp` 40–45、62：对齐加法、地址加法和数组乘法无 checked；79、85 的空状态指针减法也需安全语义。
- `Memory.cpp` 184–185、267、275：最终页面取整与 POSIX 附加长度仍会溢出。`user_addr + size` 上界比较不能代替溢出检查。
- POSIX 上巨大 size 的取整可能回绕为小映射；Windows 的零大小 VirtualAlloc 通常会失败，不把 POSIX 推导泛化为两平台实测。
- 明确 alignment 原始输入语义；失败保持 arena cursor 和 realloc 原块，使用偏移/剩余容量检查。

验收：`SIZE_MAX` 邻域、数组乘法、巨大 2 幂 alignment、0/3/12/24、未初始化 arena、耗尽；失败不返回伪成功小缓冲区。

### K2-B：普通 new、断言和帧初始化

- `IDPlugin/Stub/IDPluginStub.cpp` 10–18、30–38：普通分配函数失败直接返回空，违反普通 new 契约；nothrow 可返回空。
- `BootstrapLog.hpp` 71–79 与 `Common/Core.hpp`：MSVC debugbreak 后可继续；统一不可恢复路径应不返回，可恢复参数错误显式返回失败。
- `Memory.cpp` 130–138、322–325：帧分配失败未通知，却继续报告初始化成功；设计明确失败结果与安全空状态。
- OOM 日志可被可分配 sink 接管，需紧急不可分配通道或重入防护。Fatal 日志级别本身不等于终止。

验收：对 slab、large、frame 注入 OS 失败；普通 new 测试终止语义，nothrow 返回空，realloc 原块仍在；断言不能恢复后继续非法路径。

### K2-C：C++ 存储生命周期

- `SlabSpan::format` 在 OS 存储上直接写成员并操作 atomic；显式构造元数据，审查用户对象与侵入式 free node 的生命周期切换。
- `SlabSpan::format` 公共输入目前只检查节点大小，奇数块大小可能不满足节点对齐；当前 15 档并未因此失效。
- 将标准层面风险与实际运行复现区分，不宣称已证实优化器故障。

K2-B 涉及 Stub，必须扩大本次授权范围；异常禁用不能作为普通 new 返回空的理由。

## 5. 工作包 K3：生命周期状态机与事务回滚

**证据：** `PluginManager.cpp` 57–63 无重复初始化检查，183–203 所有 register 先执行，213–234 只按 initialized_count shutdown/unload。注册只看最终布尔值，回调期间可追加插件或重入。

**实施目标：**

1. 明确 Registering/Initializing/Running/ShuttingDown 等状态及允许操作；回调前切换状态，拒绝递归初始化/关闭与结构性注册。
2. 分别跟踪已注册与已初始化；失败关闭成功 init 前缀，卸载全部已 register 插件。
3. 决定失败 init 的部分资源由其自行清理还是由专门失败回调处理；不盲调未就绪插件的普通 shutdown。
4. 统一缺依赖、环、init 失败后的注册表保留/清理策略，明确是否可重试。
5. 冻结描述符及依赖；const 指针不能阻止原对象被改写。先决定契约，再选择复制或不可变约束。

**验收：** 首/中/末 init 失败；重复 init/shutdown；register/init/shutdown 回调重入；初始化期间新增插件；严格回调次数与顺序；0/128/129 插件和 32/33 依赖边界。

涉及回调签名/重试 API 的变化由主 Agent 确认。

## 6. 工作包 K4：服务槽、后端选择与依赖一致性

**缺陷：** `Plugin.hpp` 108–122 无槽边界、所有权和类型校验，后写覆盖；`PluginDependency::slot` 只做诊断。关闭没有兜底清空。

**关键场景：** A 无依赖，D 兼容 A/B，B 依赖 D；拓扑 A→D→B 合法。但所有 register 完成后 B 覆盖共同槽，D init 使用未初始化 B。或者合格后端被旧版后端覆盖。拓扑版本达标不等于实际 API 达标。

**实施目标：**

- 明确唯一活动槽提供者，或设计独立句柄支持真正多实例共存；不能靠最后写入选择。
- 保证编译分支、依赖满足候选、版本与实际提供者一致。
- 不把 OR 关系简单固定为注册顺序第一个候选而引入假环；记录/制定正确选择策略。
- 注册阶段校验槽合法性、API 类型/版本/大小与归属；Debug 提供错误诊断，保持热路径轻量。
- 失败和关闭兜底清空；插件解绑不得误删另一个提供者的槽。

**验收：** MaxSlots/非法枚举、空槽、冲突槽、错误表类型、旧新版候选、OR 打破环、关闭清空、初始化期间依赖调用就绪。

先交主 Agent 决定后端选择和公共 API，不擅自新增完整业务框架。

## 7. 工作包 K5：线程退出、孤儿页和 POSIX 映射

**证据：** `Memory.cpp` 61–147 TLS 无回收，328–331 Shutdown 仅日志，275–301 POSIX 返回对齐内部地址后未完整解除映射。

**实施目标：**

- 为线程注销、Slab 存活块和孤儿页建立所有权协议，处理线程 A 退出后 B 的晚释放。
- 不直接析构释放全部页；当前主要是泄漏，草率回收会引入 UAF。
- 可先明确固定线程池的边界和显式 detach，再增加空页回收与接管；证明在途生产者和内存屏障。
- 回收帧 arena 前保证所有使用者退出；TLS 地址复用不能被当成永久身份。
- 修 POSIX 原始映射/裁剪和失败返回、统计。当前只保证 Windows，平台扩展须说明支持范围。

**验收：** 短命线程反复创建、晚释放、多生产者重叠、空页回收、真实 OS 映射稳定性，而不是只看已扣减的内部统计。

## 8. 工作包 K6：自举日志、ABI 与构建闭环

- `BootstrapLog.cpp` 54–57 派发 relaxed；与 release setter 配对的 acquire 才能发布 sink 依赖的初始化状态。
- 早期日志暂无回放缓存；实现时规定固定容量、溢出、切换和回放顺序。获取函数指针的同步不等于卸载安全。
- 真正插件目前未落地；Sandbox 的 Math/Physics 是宿主内嵌演示，不能验证真实跨 DLL 开销或热重载。
- 明确 `abi_version`、`struct_size`、工具链/CRT/调用约定；TypeID 函数签名哈希不是稳定布局版本。
- Stub 植入需检查真实 DLL 产物与双向释放；普通 STATIC 私链不是未经验证的强制抽取保证。
- 顶层 CMake 默认所有实体目标 AVX2，Release fast-math；设计基线硬件与模块数值选择。
- 构建 OFF/ON 输出共享源码树 `bin`，同配置的 import/static `ID.lib` 等可相互覆盖；隔离模式/配置/构建树。
- ID/Sandbox GLOB 未带 CONFIGURE_DEPENDS；显式列表或自动重新配置。
- POSIX Sandbox 无条件 CRT 对齐分配调用需处理，不能只因为有 GCC 分支就声称跨平台可用。

验收采用真实独立插件、不同模式构建、实际在途调用安全点；不在本任务擅自实现 Math 业务。

## 9. 测试与性能后续

当前测试为 Sandbox 冒烟/基准，没有独立 CTest 用例注册。512 个 64B 块不耗尽约 1022 块容量的 Slab，随后单次分配不能证明 harvest 发生。remote 基准的生产者/消费者分阶段执行，不足以验证 exchange 与多生产者 CAS 重叠。

按工作包同步加入回归，测试和共享 CMake 串行分配给一个任务。普通 new 的终止语义在独立进程验证。若当前缺编译器、构建或运行环境，报告未验证并保留状态。

正确性完成后再优化：满页越多，慢路径从全链表头重扫越长，可设计可分配页/满页分类和远端归还通知；先证明不丢通知，再测收益。记录峰值保留内存、碎片、慢路径比例与 P99 延迟，不只测平均吞吐。OS 与日志路径不承诺实时有界。
